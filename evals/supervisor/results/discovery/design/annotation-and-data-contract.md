# 标注规范与数据契约

版本 design-v1；2026-10-21。此规范是新产物；没有宣称完成标注。原样本、文档和标注者尚未取得。输入材料为虚构情景，字段设计是本项目提案。

## 1. 三层信息分离

| 存储层 | 字段 | 谁能读取、什么时候 |
|---|---|---|
| agent-visible | opaque `case_id`、用户当前消息、已发送历史、可用参考时间/范围、文档片段与元数据、允许动作和任务要求 | 路由/回答系统在 O0 时读取；opaque ID 不编码 family/label |
| environment-private | 语料完整版本、真实用户状态、允许澄清问题及回复分支、检索返回规则、调用预算 | 环境在合法调用后只返回该动作可取得的信息；不把完整场景随返回一起交给模型 |
| evaluator-private | `reference_intent`、相容意图集合、答案/证据集合、family/split group、切片、标注与裁决、金标约束、预测外的评价辅助字段 | 运行结束的评分端；评估状态不得回流调参 |

只采用公开字段 allowlist 构造模型输入，不用“删几个已知泄漏字段”的黑名单。集成检查要改变隐藏标签而保持可见输入不变，确认候选构造的 prompt/路由输入不变；环境回复按协议变化是允许的信息获取，不属于泄漏。更换 case ID 不应改变规则输出。进程隔离与日志审阅负责验证实现；JSON 字段分组本身并不提供安全隔离。

`annotation-template.json` 是空白登记表，不是样本。任何 null 都表示待填/未知，不能作为默认零分、无歧义或同意数据许可。

## 2. 核心构念

**意图集合 Z(O0)**：标注者根据用户已表明内容与公开上下文列出仍相容的实质目标，排除与文字明确冲突的解释。不要把完整场景中的真实意图倒灌到 O0。记录每个候选的文字依据和排除依据；合理多解保留。

**答案敏感性**：若存在 z1、z2∈Z(O0)，所要求的实质答案/操作约束不同，记 `answer_sensitive=true`。存在多个词义但正确任务结果相同，记 false；缺文档不能验证则 unknown。不同参考答案措辞但语义等价，不构成答案敏感。

**无追问完整回答是否存在**：独立记录 `robust_complete_answer_exists`。即使实质答案随意图变化，清楚列出条件并满足用户要求也可能是合格回答。只有在任务要求确实需要唯一结论或无法给出完整条件答案时，才将追问列为可能必要的动作。禁止为了形成正面结果临时收紧条件回答的 rubric。

**证据状态**：初始片段是否能支持所有必需结论；若不能，授权语料中是否有合适证据。分为 sufficient / missing_retrievable / missing_unavailable / conflicting / unresolved。检索器没召回和库里根本没有是两种失败，不混成一个“知识不足”标签。

**任务版本状态**：explicit_resolved / unspecified / unresolved_reference / not_applicable。`explicit_resolved` 要同时解析版本、参考日期和适用范围；“去年”若时间锚点未知，不能标 resolved。旧版本只要符合任务要求就有效。当前有效约束应保存原始话语出处、覆盖/撤销关系及生效时点；首轮无多轮轨迹时不填造。

**澄清信息价值**分四项登记：询问是否针对真实缺口；用户是否知道且能提供；回复是否排除足够多的相容世界；回复后是否实际改善任务结果。只有前三项也不能直接写净效用为正，成本与失败概率另记。

## 3. 标注流程

1. 登记来源、许可、家族谱系、文档版本与哈希；没有原始材料的记录保持 blocked。
2. A/B 两位标注者分别先只看 O0，列相容意图及可见约束；保存后再看完整场景和文档，形成每个意图下的答案与证据集合。两阶段分开记录，防止只照隐藏意图写“唯一解释”。
3. 逐轴判断答案敏感性、证据状态、版本可解析性、完整条件回答可行性和用户答复范围。每项附文档段落/话语位置。
4. 保存分歧标签和自由解释。裁决者检查来源；分歧源于材料不充分时标 unresolved，不通过多数投票造确定性。分歧源于 rubric 不清时版本化修订，并重标所有受影响的开发项。
5. 先在开发家族校准；固定 rubric 后，评测集标注者不看模型输出和方法名。若模型输出暴露了新的合理答案，记录协议修订及其事后性质，旧测试不再充当未触碰确认性结果。
6. 质检覆盖每个基础家族、每种关键切片与每个反事实对；变体核对语义是否保持，不能只抽几条流畅性样例。

团队人数和人工时间未落实；上述“双人”是有效性设计要求，当前没有伪造标注者或一致性数值。

## 4. 问题、回复和动作接口

核心诊断中的动作对象：`answer`、`conditional_answer`、`retrieve`、`clarify`、`abstain`。每一步记录时间、可见输入哈希、动作参数、环境回复、后续输出、预算消耗和状态。

- `retrieve(query, version_filter)` 只访问冻结语料；合法目标版本未知时不能从金标补过滤参数。
- `clarify(question)` 先按题目 rubric 判断是否问到了可提供的缺口。开放式“你什么意思”若无法映射到脚本，不自动送上全部意图；记 question_invalid/response_insufficient 并保存原问句。
- **理想澄清轨道**固定一条经标注者审定的目标问题与诚实回复，只用于测可获得信息上界；不声称测了 Agent 的问法质量。
- **策略轨道**由候选自己决定问法，按预先脚本返回足够/不充分/不知道/拒绝四类之一，保持隐藏世界一致。无法匹配问题由盲评裁决并登记，不能为某方法即时改脚本。
- 核心诊断动作上限是一次信息获取与一次终止回答。混合缺口需要两次获取的情况单列扩展，并记录动作顺序，不把单步预算下失败归咎“澄清无效”。

## 5. 最终回答评分 rubric

每项评分是二值 + unknown，不使用无法复核的整体印象分。

| 分项 | 通过 | 失败/不可判的具体情形 |
|---|---|---|
| answer_correct | 与完整场景允许的实质答案集合一致；条件答案满足任务要求 | 错结论、遗漏必须信息、把假设当确定；原文不足则 unknown |
| constraints_satisfied | 遵守当前有效版本/时间/范围；已撤销条件不再支配答案 | 用最新版替代用户指定旧版；引用不适用地区/日期 |
| evidence_supported | 所有核心断言有相应授权证据支持 | 文档中没有依据、引用段落不支持；仅复述用户偏好不要求文档证明偏好本身 |
| provenance_correct | 引用文档和版本真实存在且适用于对应断言 | 内容似乎正确但引用了错误版本或不存在证据 |
| task_completion | 用户请求得到满足，包括合理条件答案/允许的保留结论 | 应给结果却全弃答；需要唯一结论时只列未解决分支 |

严格成功 S=1 要求所有适用分项通过；不适用项用明确规则排除，不能默认通过。各分项和 unknown 个数也单独报告。若任务的正确行为就是声明信息不足，只有 rubric 事先允许且说明具体缺口的弃答可判完成；将风险覆盖曲线与成功率并报。

路线标签 `admissible_actions` 是解释性集合，来源于任务信息结构与可实现结果，不强行指定唯一 `best_action`。若两种动作都达到相同质量，但成本权重未知，记录 Pareto 并列；不凭标注者偏好判“最优”。

## 6. 错误分类与登记

允许多个并存标签：intent_unidentified、version_parse_error、version_filter_error、evidence_not_retrieved、evidence_absent、context_or_generation_error、question_irrelevant、user_unavailable、answer_unchanged_after_question、invalid_action、timeout、parse_failure、label_unresolved、hidden_information_leakage、split_contamination。每项需记录发生层和证据。

主分析不得删除失败调用。对标签未解决、源材料损坏、预算超限和代码错误分别记原因；任何排除须在看结果前按规则执行，事后排除进入 amendments 并给含/不含敏感性分析。最终按家族和切片列出分母，而非只展示成功示例。

## 7. 标注验收与返工条件

所有进入主要比较的样本必须有可追溯来源、完整信息边界、版本/答案/证据依据和无未解决的关键构念冲突。未通过者留在争议集并报告比例。此要求是数据可解释性的门槛，不是追求全体一致率 100%。

只要出现“用隐藏意图界定可见唯一意图”“无理由拒绝合法条件回答”“规则靠金标取得版本”“反事实双方的初始观察实际不同”中的任一问题，该病例不能进入对应机制比较，先修数据/定义，再重新冻结新版本。保留旧版本与修改理由。
