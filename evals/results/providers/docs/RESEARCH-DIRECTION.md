# 可继续探索的方向：时变意图与撤销约束

日期：2026-10-20。状态：**`proposed`，真实近邻工作未核实，实验未执行。** 所有本地“论文”均为教学合成片段；本文件给出可被支持、限定或推翻的问题结构，不作新颖性或效果保证。

## 1. 问题锚点

**问题：当用户在多步任务中修正目标或撤销某项授权，系统能否让尚未提交的动作使用当前有效约束？如果仍执行旧动作，主要原因是意图标签有误、更新没有传到执行层，还是撤销到达时动作已经提交？**

本轮把方向挂接到 `intent`、`clarification`、`routing`、`memory`、`planning`、`tool-use` 与 `safety-security`，新增 `temporal-intent-revocation` 域。新增域保持 `coverage:unsearched`，因为尚无真实文献检索；三份本地合成片段的阅读单独记账。

研究对象是有显式目标变更、约束取消或任务撤销的决策智能体。核心接口为“最新意图/约束 → 当前计划 → 动作提交”。本轮不扩展到所有长期个性化、训练期机器遗忘、法律意义的数据删除或任意异步事务系统。

不可变边界：0 付费；本轮仅本地阅读、分析、文件整理与校验；不得联网、探测账号、安装依赖、执行研究负载或发布。成功条件是保存准确的证据边界、查询计划、机制候选、反证路径和交接状态，而非获得实验上的正结论。

## 2. 需要先区分的概念

| 概念 | 本项目的工作定义 | 容易混淆之处 |
|---|---|---|
| 意图修正 / intent revision | 用户改变任务目标或参数，旧目标的部分内容可能仍有效。 | 不能默认新消息取代整段历史；指代和作用范围仍需判定。 |
| 撤销 / revocation, cancellation | 对特定目标、约束、授权或待执行动作撤回先前承诺。 | 取消一个动作不自动取消所有后续任务；已完成动作不能被表面确认“取消”所逆转。 |
| 有效时点 / effective time | 某项约束对任务应当开始或停止生效的时间。 | 接收时间、事件发生时间、声明的生效时间与执行时间不是同一量。 |
| 澄清噪声 / noisy clarification | 用户回复含歧义、错误、矛盾或不完整信息。 | 反例提示不能假设每次澄清提供正确标签。 |
| 动作提交 / action commitment | 系统越过当前环境定义的可阻止边界。 | 必须由真实工具语义定义；请求发出不必然等于不可撤销完成。 |
| 撤销后恢复 / post-cancellation recovery | 对尚未提交任务停止或改计划；对已产生副作用的任务核实状态，并在有授权且可行时补偿。 | 补偿通常不是严格逆操作；不要把补偿成功等同于从未产生副作用。 |

这些是待落实到环境的操作定义；未来取到原始论文后，应记录其不同术语与边界，而不是强迫所有工作符合本表。

## 3. 支持与反驳如何影响候选

`local-support` 只说明一个合成设定中的不确定性路由可能减少错误，`local-counter` 指出带噪澄清可以使同机制失效。故新问题需要同时检查**正确意图是否已知**与**正确约束是否被执行**。将二者分开，有机会判断应修标签、澄清策略还是执行接口。[来源：`papers/support.md`、`papers/counter.md` 第 1 行；详细边界见 `EVIDENCE-LEDGER.md`。]

既有 `past-decision` 继续暂停：标签歧义未经检查，不能先认定模型错误并增加关键词。只有经独立于被测模型的标签判定确认“语义标签本来正确，但更新没有到达执行层”，才值得进入执行接口机制检查；若标签本身有问题，先修标签定义和测量。[来源：`seed-batch.json` 的 `past-decision`；路由域原有笔记。]

## 4. 主候选与最强替代解释

**主候选 H1：**在撤销已经对执行层可见、动作尚未越过可阻止边界的条件下，执行前对意图版本、约束作用范围与撤销状态进行复核，可能减少沿用旧意图的副作用；这种变化应能与更好意图标签、更多澄清次数和额外计算区分。

这首先是一个接口失效与测量问题。版本号、取消标记或规则检查本身都不构成创新。若强规则基线已解决全部现象，应把“新方法”主张暂停，转为边界分析或停止该方法路线。

| 候选解释 | 可区分的预测 | 最小改变判断的检查 |
|---|---|---|
| H1：更新与动作提交未保持一致 | 即使给定正确当前意图，旧执行链仍可能违反撤销；执行时复核可减少此类错误。 | 固定同一正确意图输入，替换执行边界检查，观察实际动作而非回复措辞。 |
| R1：标签歧义或意图解码错误 | 换成正确标签后错误基本消失，执行层附加机制无明显额外作用。 | 先审标签来源与歧义，再用 oracle 中间输入定位；oracle 结果不能作为部署性能。 |
| R2：简单规则已足够 | 最新有效约束表与确定性取消检查达到同样结果。 | 与规则实现充分的强基线同信息、同预算比较；不能只比较弱“最后一条消息”实现。 |
| R3：收益来自更多等待、澄清或计算 | 在等待时长、澄清预算与模型调用一致后，收益消失。 | 匹配信息与资源，另报自然成本；控制“不做任何动作”获得的表面安全收益。 |
| R4：撤销到得太晚 | 错误集中在动作已提交后，执行前复核也无法避免。 | 明确接收、可见、提交、完成时点；分开报告可阻止与已提交样本。 |
| R5：检查与提交之间存在竞态 | 即使复核通过，撤销仍可在提交前插入而造成旧动作。 | 后续在可控环境检查复核与提交是否同一原子边界或有等效版本校验。 |
| R6：澄清越多噪声越大 | 增加不确定性澄清可能增加误取消、反复计划或漏做合法任务。 | 独立改变澄清噪声与是否撤销，保留反例和错误取消率。 |

## 5. 操作方法卡与未来最小判别设计

本节是设计文件，尚未建立可运行基准、冻结实验或执行任何研究程序。

每段轨迹至少需要：原始任务与时间线、权威用户更新、目标/动作的稳定 ID、约束范围、事件顺序/有效时点、各组件看见的意图版本、动作状态（待处理/已提交/已完成）、实际副作用以及单独记录的澄清噪声。记录时间与内容不能泄漏未来撤销事件给更早决策。

实验单位应是完整任务轨迹；同一模板、用户或任务族的变体属于相关样本，不能把每个动作或重复生成当成独立新任务。独立保留开发与评测任务族，报告失败轨迹和被排除样本的理由。真实数据、许可、标注和环境均待核实。

建议按依赖顺序分三块，避免一次比较同时改变所有组件：

1. **标签与时序诊断。** 明确目标变更/撤销的正确标签和工具提交边界。比较原输入与正确中间意图输入；涵盖无更新、参数修正、显式撤销、歧义澄清、撤销后再授权和提交后撤销。
2. **执行复核。** 固定意图输入和动作预算，比较仅在路由时读取约束、确定性当前约束/取消检查、版本化作用范围与执行提交复核。相同任务使用相同可用信息，不能让候选额外看到未来事件。强规则基线必须实现正确的作用范围与撤销语义。
3. **澄清噪声边界。** 只有前两块仍有未解释现象时，再研究不确定性引导澄清是否有增益。单独控制澄清次数、输入噪声和等待预算；保留原反例的条件，不把它排除于评测。

主要结果应同时观察：撤销已可见且仍可阻止的动作中违反撤销的比例、合法任务完成率、错误取消率。过程记录包括更新传播时延、旧版本读取、复核后到提交的间隔和恢复结果；成本包括调用、澄清、等待、重试和通信。已提交后才到达的撤销另报，不藏进前者分母。

样本量、最小有用效应、非劣边界与置信区间方案目前**未确定**。先取得环境、基础发生率与用户可接受损失范围，再按轨迹/任务族依赖选择估计方法；不能凭三句片段指定精确样本量，也不能用“不显著”声称规则与候选等价。

## 6. 事先写下的继续、改向与停止条件

| 未来观察 | 结论边界与下一动作 |
|---|---|
| 标签修正即可消除现象 | 主要机制归因转向标签/澄清测量；继续暂停扩大关键词与复杂执行机制。 |
| 强规则取消基线与候选表现相当，且估计精度足够 | 方法差异不足；保留结果并暂停“新方法”主张，可评估是否还有明确的测量贡献。 |
| 复核在正确标签、同预算下减少可阻止的旧动作，且合法完成率达预定要求 | 仅在该任务、边界与信息条件下提供初步支持；仍需真实任务、近邻工作与独立检验。 |
| 更安全仅因为停做任务或等待更久 | 不支持当前机制/效用主张；重新设计效用约束或停止。 |
| 噪声澄清使收益消失或误取消增加 | 缩小适用边界，保留相关反证，考虑无需澄清的规则路径。 |
| 事件语义不清、标签不可靠或样本不足 | 结果不可区分；修测量，不把它归为假设成立或已被反驳。 |
| 已有最近工作在同目标、信息、机制、评测条件下回答问题 | 缩小到未被覆盖的边界或停止重复方法；不得仅换术语继续声称创新。 |
