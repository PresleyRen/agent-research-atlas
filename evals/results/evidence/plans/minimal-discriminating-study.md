## 问题锚点与方法卡

**问题：** 在信息不足的二路由请求上，针对缺失意图信息提问一次，能否比通用追问一次增加有意义的正确路由？

**机制预测：** 增益应来自得到与最终意图有关的信息。在请求确实有歧义、答复能区分目标时更明显；同等长度的无关答复不应产生相同收益。相同语义的表面改写不应把收益完全抹掉。

**最强竞争解释：** 任何一次通用追问带来的额外信息已足够；并不需要针对性问题选择。另有评价器常量、参考标签歧义、真值泄漏、出现“文档”一词即触发search、开发案例过拟合等解释。

| 方法字段 | 将来必须实现的操作定义 |
|---|---|
| 输入 | 当前请求文本与任务允许的路由集合；候选看不到参考标签或未来答复 |
| 目标路由 | 先定义search与chat的边界；多路由合法时记录允许集合或暂不作单一准确率判定 |
| 候选问题选择 | 根据原请求缺少的意图槽位使用预先固定的有限规则，最多问一次；先不宣称有学习到的不确定性分数 |
| 共同后续决策器 | 四条件共用一个冻结的本地路由器；是否看到澄清答复由干预决定，不为候选专调标签映射 |
| 输出 | 路由、是否提问、实际问题、答复、条件ID、决定依据与成本；逐条保留 |
| 训练 | 初始小诊断不训练；若后续引入训练/阈值调节，单设开发数据和新版本 |
| 评价器 | 独立文件读取不可变参考标签和预测文件，按case_id连接并计算correct/valid_n；不得从方法代码读答案或接受外部传入accuracy |
| 真值来源 | 由任务设定/用户意图确定，不从候选输出生成；标注员在看预测前判定可接受路由 |
| 答复来源 | 离线预先写定的、与隐藏意图一致的答复规则；不给模型直接暴露search/chat标签代码；不同问法的答复可能含不同信息，这正是需操纵和记录的变量 |
| 最简单替代 | 通用追问一次，例如固定请求用户补充实际目标；另保留旧关键词路由作历史弱基线，不将它视为唯一强基线 |

## P0：进入研究前的最小计量修复

1. 找回资源说明所称八条合成案例；没有案例就登记缺失，不能从日志恢复出虚構的五对三错。每例至少保留`case_id`、`family_id`、`text`、隐藏意图、原始标签、允许路由、歧义类型、标签来源、版本。
2. 在不看方法预测的情况下完成标签边界检查；若只有一名审查者，明确是单人复核。分歧与无法判定行保留，不为提高成绩删掉。先使用现有八条作开发材料。
3. 从计量代码中移除硬编码准确率，另写冻结评价器。实现与测试必须在后续授权的执行轮完成；本轮只记录所需校验：手工可算的全对/全错/部分对、空输入、重复ID、缺失预测、非法标签、错位顺序。设计检查不是已经跑过的测试。
4. 输出逐条预测与正确性、n_total、n_valid、n_missing、n_ambiguous、排除理由；计量函数由此重算汇总。源码、输入、真值、评价器与执行记录分别留哈希。

**P0通过条件：** 每项有可追溯ID和标签来源；汇总能逐条重算；空分母不返回有效准确率；原日志来源若找不回，继续保持历史未核验。P0不能验证澄清效果，也不是一次新的性能成绩。

## P1：四条件配对诊断

每个原始意图案例在所有条件评估；独立单位是原始意图/场景family，改写、同场景多答复、种子都嵌套其中。先对恢复的八个开发案例进行小规模诊断，最多八案例×四条件=32次路由判定；这只是给定已有材料数的运行上限，不是有统计功效依据的样本量。

| 条件 | 得到的额外信息 | 次数与比较作用 |
|---|---|---|
| B0 不问直接路由 | 无新答复 | 0问；展示一次提问的实际总收益与代价，不能单凭它证明针对性策略 |
| B1 通用追问一次 | 按固定通用问题给出的合法用户答复 | 1问；主强基线，与C共用后续路由器和预算 |
| C 针对性澄清一次 | 对候选选定缺失槽位的合法答复 | 1问；主比较为C−B1 |
| B2 无关追问对照 | 等长度但与路线无关的答复 | 1问；分离相关信息与额外文本/轮次效应，不解释为现实最优策略 |

所有提问条件使用同一预定字数/字符上限、一次回答、一次后续判定；实际长度和操作耗时都记录。建议开发版问题和答复各最多40个中文字符，这仅是待冻结的共同上限，不是对用户时间或模型token的精确等价。P1目标是局部机制诊断；真实交互成本/用户体验仍需后续研究。没有API、GPU、联网或付费模型。

在每个独立case中，以固定顺序表或由冻结顺序种子打乱条件顺序，并每次重置状态，防止前一条件答复泄漏到下一条件。顺序随机化不能凭空制造独立样本。

### 排除词面捷径

数据审查阶段记录原请求与答复是否含“文档”，确保它不是参考路由的唯一决定性线索。另为每个原始案例计划一个保持意图的同义改写，形成最多64次总判定（8×2版本×4条件）；改写仍归属于同一family，不能把n从8变成16。该扩展只在32次阶段无法区分词面触发且后续授权仍允许时实施，不能看见正结果后只保留有利版本。

如果通用追问与针对性问题的答复信息相同，预期相同结果；如果针对性答复具有更多信息，需通过信息编码/槽位完整性记录呈现这一差异，不能把“信息不同”误称所有条件信息已匹配。B2有意改变信息价值而保留轮次与长度。

## 主要测量与不确定性

- 主结果是相同case/family上C与B1的正确路由差、改对数和改错数；按预先标注的歧义/无歧义分层展示。没有有效标签的案例不默默移出分母，单独报告。
- 过程结果是问前/问后目标信息槽位是否充足、答复是否相关、路由是否变化、是否依赖“文档”字面。过程标签由既定规则给出，不能用候选置信自评代替。
- 成本报告每例提问数、字符数、路由调用数与可测本地耗时。非API场景不编造token或美元成本。
- 对八个开发案例逐例展示配对差异和family依赖；不以它们做普遍性结论。后续独立评测再按family汇总配对效应与区间，选择能处理该依赖的分析方法。
- 不预填p值、方差或效果大小。真实确认实验在知道数据生成方式与有意义改进界值后设计样本量；固定小样本只能作有限诊断。新增seed不能补偿缺失的独立场景。

## 预先写出的决策分支

| 观察 | 解释边界 | 行动 |
|---|---|---|
| 无法获得有效标签或逐条汇总失败 | 计量无效，研究问题无法判断 | 停在P0，不根据旧准确率继续调参 |
| C不优于B1，二者都优于B0 | 通用额外信息可能解释全部收益 | 停止更强“针对性策略增益”论点；保留较窄信息价值问题 |
| C优于B1，且相关答复优于B2，改写保持方向 | 与候选机制的有限预测相容；仍可能是样例选择或模拟答复偏差 | 仅作探索线索；在新场景、独立保留标签和冻结规则后复验 |
| 只有含“文档”的表述有效，改写后收益消失 | 词面触发可解释观察 | 停止语义澄清机制解释，转向错误分类/路由表示问题 |
| B2与C同样改善或评价器对错预测无区别 | 额外文本、评测泄漏或实现问题仍可解释 | 优先回查数据链和指标，不能升级假设 |
| 差异由单一family决定或改对改错相互抵消 | 稳定性与实际价值不明 | 保留原全部结果，标记inconclusive解释，补最有区别的独立场景 |

开发阶段的“优于”只指配对净改对为正且逐例结果可解释，不设伪精确显著性门槛；不能据此升级普遍性论点。真正确认研究需在看新结果前确定至少多少改善值得增加一次打断，并用该界值决定精度或样本量。
