# 问题锚点：版本与意图缺口如何改变路由

版本：2026-10-20 / v1。**SYNTHETIC 教学项目；本文是研究设计，不是实测结果。**

## 当前问题

当文档存在多个版本、用户说法不能唯一确定所需版本时，Agent 在**直接回答、追加检索、先澄清**之间应怎样选择？先判断哪些错误可以由可观测的信息缺口解释，再考虑是否需要新路由方法。目标版本可以是旧版本；“最新文档”不能自动代替“用户适用版本”。最后一句是本项目的设计约束，而非已验证经验结论。

已有材料提供两个值得区分的线索：证据取自旧版本，以及用户没有明确目标版本。开发笔记还描述重复取回旧片段和询问版本后歧义消失，但没有逐例记录，不能据此判断发生比例或因果。[S03：开发笔记，全文](observations.md)

## 保持与可调整的条件

| 类型 | 本项目的具体含义 |
|---|---|
| 目标保持 | 解释版本变化与意图含糊下的三类路由；把新增信息的来源说清。 |
| 本轮授权保持 | 只在此项目内做本地阅读、分析、整理、校验；研究负载预算为零，不联网、不安装、不付费、不发布。 |
| 已知资源保持 | 资源说明明确没有可用 GPU、商业 API 许可或已审核数据集。不能用工作流建议放松这些条件。[S04](resources.md) |
| 证据限制保持 | 五份输入均属教学材料；25 仅是资源文件中的数量陈述。本轮没有25条逐例描述、原始案例、标签或轨迹，不能视作可用独立验证集。[S01](../PROJECT.md)、[S04](resources.md) |
| 后续可调整 | 可观测信号、版本元数据格式、规则形式、每轮动作预算、诊断切片和指标；每次变化须记录与旧问题的关系。 |
| 仍待核实 | CPU诊断的具体实现/吞吐、数据权利、标注人、评价器、真实近邻论文和未来执行授权。 |

## 本轮成功条件与非目标

本轮完成三个机制不同的候选、明确首个判别工作、可续接地图、方法取舍、真实来源/技能哈希与本地检查收据。交付完成即停止。

本轮不把生成候选当作查新完成，不把规则实现的设想当作方法效果，不训练模型，不启动诊断负载。没有预设新方法必须优于简单规则，也没有预设应优先扩大 reranker。原始定位笔记与开发想法保留在原文件中。[S02：路线分类及默认偏好](../surveys/overview.md)、[S03：遗留想法](observations.md)

## 续接时必须保留的区别

- **来源陈述**：开发者觉得失败可能来自两种缺口。
- **本轮观察**：读到这段陈述，以及缺少日志、对照和可用数据的说明。
- **待检验推论**：两种缺口是否需要不同动作；路由时能否分辨它们。

详细方法、竞争解释和继续/转向条件见[候选与方法取舍](candidates-and-methods.md)及[最小判别方案](../plans/minimal-discriminating-study.md)。
