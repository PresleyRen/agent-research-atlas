# 候选与方法取舍

2026-10-20。**SYNTHETIC；全部候选尚无实测支持，真实近邻文献未核验。**

## 为什么从这里开始

定位笔记已经保留五类路线：固定路由、置信度阈值、查询重写、动态检索深度、澄清问题。它同时指出检索可能重复过期内容、澄清有用户负担，却没有比较证据来支持其“更强检索器优先”的偏好。[S02，全文](../surveys/overview.md)

开发笔记把“拿到旧版本”和“用户未说明目标版本”并列，但没有日志和控制条件。[S03，全文](observations.md) 因此本轮选择**失效分解、竞争预测、边界反例**这三种视角：它们分别产生动作来源假设、可证伪比较和不应提问/不应停止的反例。没有机械遍历框架或生成固定数量的点子。

## 三个候选

| 候选与当前管理状态 | 科学问题与贡献类型 | 机制及区分性预测 | 最强竞争解释/简单替代 | 最小判别与分支 |
|---|---|---|---|---|
| **C1 缺失信息来源与动作选择** `proposed`；先推进其诊断 | 在版本文档问答中，目标版本未定与证据不适用，是否产生不同动作收益？先争取机制边界或测量贡献。 | 澄清补用户意图；检索补可用证据。在仅缺目标版本的切片，版本澄清可能优于再检索；在目标已明但证据不适用的切片，定向检索可能优于重复问版本。关键预测是条件与动作的交互，而不是总分上涨。 | 状态无法从决策输入识别；简单版本规则已经解释全部变化；缺失是索引/元数据故障；标签错误；额外信息量或成本不同造成差异。 | 先做 M0 的信息与标签可识别性审查，再做 M1 配对四格诊断。若只能借助隐藏标签获得优势，转向可观测性/标注问题；若简单规则覆盖全部收益，保留诊断发现，停止增加复杂路由。 |
| **C2 只为会改变答案的歧义澄清** `proposed`；后续候选 | 哪些版本歧义值得打断用户？争取澄清价值的边界刻画。 | 在不同合理版本解释给出相同答案时，澄清的任务收益可能为零；只有答案随解释变化且条件式回答不足时，定向提问才可能值得。 | 收益只是更长输入或保守拒答；判断答案是否变化用到了隐藏真值；给出带版本条件的答案已经足够。 | 在 C1 后配对“版本解释不同、答案相同/不同”的场景；与固定提问、直接条件式回答比较。若答案差异只能由评价器知道，不能宣称可部署；若条件式回答以更低交互成本同样满足任务，转向该简单策略。 |
| **C3 检索停滞是否支持换动作** `parked`；保留重启条件 | 重复取回内容何时是继续检索无益的信号？争取停止条件和失败边界的测量贡献。 | 已有轨迹中的新增相关且适用证据接近零时，继续同类检索可能不如去重、改写或澄清；只有缺口确属用户意图时才预测澄清有益。 | 重复不等于充分；后一次检索可能找到新证据；证据根本不在语料中；查询或排序实现有问题。 | 必须先取得逐次查询、返回文档ID/版本/顺序和成本。对照“表面停滞后可恢复”与“确无可用证据”，比较去重＋版本过滤＋一次改写、固定深度上限与候选。当前无轨迹，不选择停止阈值；取得轨迹并完成C1之后才重启。 |

这三个候选不是三个已证明的新算法。C1 的第一版规则可能与强简单基线重合；在查新与判别完成前，不能仅改名就宣称方法创新。C2 是进一步减少不必要提问的备选；C3 尚缺其核心输入。

## 最近工作与确切差异：目前能写到哪里

| 候选 | 当前最接近的**本地方法家族** | 计划检验的差异 | 真实论文身份与差异状态 |
|---|---|---|---|
| C1 | 固定路由、置信度阈值、版本过滤、澄清 | 在同一信息接口下，区分缺口来源是否比统一低置信度标签更能解释动作收益 | 未检索、未核验；无可引用真实 paper ID |
| C2 | 固定澄清、意图消歧、条件式回答 | 以任务答案对版本解释的敏感性刻画提问价值，并计算获取该信号的代价 | 未检索、未核验；不声称旧工作没有做过 |
| C3 | 动态检索深度、查询重写、去重与固定上限 | 停滞信号的可观测性，以及继续检索/澄清/保留未解决状态的边界 | 未检索、未核验；没有确定阈值 |

上表仅用于确定下一轮查什么。本地综述无 DOI、没有真实出版身份，不能冒充最近论文。[S02](../surveys/overview.md) 双语近邻与反证任务及 `not_run` 回执见[检索续接表](../plans/retrieval-followup.md)。

## 方法卡：C1 的最小可操作版本

| 项目 | 定义与边界 |
|---|---|
| 输入 | 当次问题、被允许使用的对话上下文、已经取回的片段及其文档家族/版本/适用时间/出处、截止当前的动作轨迹。没有这些字段时保留 unknown。 |
| 输出 | `answer`、`retrieve`、`clarify` 中一个动作，附实际依据；动作后记录已解决/仍缺目标/仍缺证据/二者都缺。预算耗尽时保留未解决状态，不强造成功。 |
| 内部表示 | 可观察的目标绑定状态 `明确/不明确/未知`，证据相对已知目标的适用性 `支持/不支持/不可判定`。目标未知时不能偷偷用真实目标把片段贴成过期。 |
| 训练/学习信号 | 首轮不训练；先用人工审阅过的确定性规则作诊断。是否需要学习，在简单规则表现及查新之后再判断。 |
| 推理信息流 | 从请求及上下文提取明确版本或日期约束 → 仅按可见元数据审查适用性 → 有充分可用信息则回答；目标已明但缺支持证据则定向检索；目标不明且当前无法给出合格答案则澄清版本。两缺口并存时，一步可能不足。 |
| 已有/新增组件 | 当前项目没有可执行基线或评价代码。新增的是信息接口、标签定义、比较表与记录协议；没有交付新的训练器或声称实现已有组件。 |
| 强简单替代 | 总是直接回答、总是问版本、总是检索，以及明确版本匹配＋必要时固定提问的规则；不得故意削弱规则基线。 |
| 评价器与真值 | 由后续独立整理者依据任务出处、用户意图记录和完整版本文档建立；隐藏目标与有效性标签只供评价器。初始诊断先测信息缺口是否消除；没有生成器时不报告问答准确率。 |
| 尚未定义/未核实 | 原始案例、可信版本元数据、用户答复接口、答案判定、CPU可执行实现、操作成本、效果大小、新颖性。 |

“没有写版本号就澄清”只是一个可比较规则，不是真值定义。评价应检查动作后的信息/任务结果与用户负担，不能把选了预设动作本身当成功。C2 中答案差异、C3 中未来检索结果都不得预先提供给路由器。

## 遗留方向与本轮决定

“先堆一个更大的 reranker 再看总分”仍原样保留在[S03](observations.md)，图中记录为 `parked`。暂缓理由是未确定重排是否修复目标机制、缺比较数据且当前无执行预算；它没有被科学反驳。只有后续证据表明正确版本已被召回但被排序/上下文选择压制，且简单版本过滤不足时，才将 reranker 升级为有针对性的候选或强基线。

当前优先级来自**哪项未知最能改变下一步**：先 M0；通过后设计/核实 M1；C2 随后；C3 与大 reranker 暂存。本轮没有把任何候选提升为 `grounded`、`testable` 或经验支持状态。
